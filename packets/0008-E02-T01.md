## Context

This landing zone serves only itself. Its workload identity pool provider trusts one subject
prefix — this repository's — and there is no artifact registry at all.

`work-tracker` needs to publish a container image. Its session stopped and said exactly what
was missing rather than inventing it:

> no Artifact Registry host, project, repository, or image path is tracked or configured
> the GitHub repository has no Actions variables… naming a platform-gcp workload identity
> provider or publishing service account

This packet supplies both. **You author it; the Founder applies it**, because it creates
cloud identity and trust policy — one of the four things no agent in this organization holds.

**The trap that has cost this portfolio repeatedly:** the subject must be the **immutable
claim form**, `repo:<owner>@<org-id>/<name>@<repo-id>:<claim>`, with both numeric ids. The
familiar `repo:owner/name:...` shape is mutable — delete a repository and recreate it under
the same name and it silently inherits the trust.

Read `main.tf`. The existing provider uses `assertion.sub.startsWith(...)` against a prefix.
**Consider whether a prefix is the right shape for a second tenant**, and say what you chose.

## Goal

`work-tracker` can push a container image keylessly, and can do nothing else.

## Boundary

**Author only. Do not apply.** `tofu init`, `validate`, `plan`. If a command would mutate
cloud identity, stop — including creating the registry "just to test the path".

**Do not widen the landing zone's own federation.** A second identity is a second identity.
If the simplest change is to loosen the existing `attribute_condition` to match both
repositories, **that is the wrong change** — say so and add a separate provider or a separate
service account with its own condition.

**Push only.** The publishing identity must not read state, alter IAM, or deploy. Deployment
is a different authority and a later packet.

No credential, no key, no secret. Federation is the point.

## Done when

- An **Artifact Registry** repository exists in the configuration for product images, in the
  landing zone's region, with a stated cleanup or retention posture.
- **A federated identity for `work-tracker`** is authored, matching its **immutable** subject.
  A mutable-form subject must be rejected by the configuration, demonstrated with a negative
  case.
- **The landing zone's own trust is unchanged.** Show the diff proves it.
- **The publishing identity can push and nothing else** — no state bucket access, no IAM
  mutation, no Cloud Run deploy. Enumerate its permissions in the evidence.
- **Outputs publish the consumer contract**: the workload identity provider resource name,
  the service account email, the registry host and repository path. A consumer must be able
  to read these without asking a person.
- **`tofu plan` is clean and the cost guard passes it.** Idle cost zero — an empty registry
  costs nothing; say what it costs per GB when it is not empty.
- **The full plan is captured in the evidence**, because the Founder approves from it.

## Check

```bash
scripts/check-ci-contract.sh
```

Then, with output in the pull request:

1. **The full plan**, unabridged. This is what the Founder approves.
2. **The cost guard verdict** — exit 0.
3. **The existing provider's `attribute_condition`, before and after.** Show it unchanged.
4. **A mutable-form subject rejected** by the configuration's own validation.
5. **The publishing identity's complete permission set**, and a sentence in plain language
   saying what applying this grants and what it does not.
6. **The outputs a consumer will read**, with real names and synthetic ids.
