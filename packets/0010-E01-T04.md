## Context

T01 moved the guard and denylist into the `cost-guard` repository and released them as a
composite action: `martcoca/cost-guard@v1` (moving) and `@v1.0.0` (immutable). **The action
takes a plan file path, not stdin.**

T02 cut `platform-azure` over and it is merged. **Read that repository before starting** —
it is a sibling at `../platform-azure`, and its `.github/workflows/guarded-plan.yml`,
`scripts/check-ci-contract.sh`, `config/cost-guard-action.txt` and
`evidence/0010-E01-T02.md` are a working template for this packet. Copy its shape; do not
re-derive it.

Until every consumer stops carrying its own copy, nothing has been de-duplicated — there is
just one more copy than before.

### The trap here

`scripts/check-ci-contract.sh` line 44 requires the literal string
`scripts/cost-guard.sh /dev/stdin` inside `guarded-plan.yml`, and line 29 requires
`scripts/test-cost-guard.sh` inside `cost-guard.yml`. **Both assertions fail the moment you
switch to the action**, and they fail in a script you have no other reason to open. They
must change in the same commit.

`guarded-plan.yml` pipes `tofu plan -json` into the guard and swallows stderr with
`2>/dev/null` on both sides. The action takes a file path; write the plan to a file under
`\$RUNNER_TEMP` and stop discarding stderr, which currently hides the reason for an
undecidable verdict.

### The interface finding from T02, which applies here

The action fails the step on **both** exit 1 (denied) and exit 2 (undecidable), and
`outcome` is `failure` for both. Telling them apart needs `steps.<id>.outputs.verdict`.
The natural reach for that on a failed step is `continue-on-error`, **which removes the
gate.** Copy the shape `platform-azure` uses: no excuse on the guard step, and a separate
`if: always()` reporting step that reads the output and re-fails.

### Pin the version once

`platform-azure` records the pinned action reference in `config/cost-guard-action.txt` and
its contract check asserts every `uses:` matches it. Copy that. It is what makes "the
version CI runs" and "the version we think it runs" the same string by construction.

## Goal

`platform-gcp` runs the released cost guard, holds no copy of it, and still fails a plan that would
create a denied resource.

## Boundary

**This repository only.** Do not modify `cost-guard`, or the other two platform
repositories.

Do not change what is denied. No type added, none removed, no price string edited. **If the
released denylist differs from the local one, stop** — that is a finding, not a conflict to
resolve.

**No cloud mutation.** No `tofu apply`, no provisioning, no IAM or OIDC change. Plan-time
only.

Pin the action to a tag, never to `main` or a branch.

## Done when

- The guarded plan workflow invokes `martcoca/cost-guard@v1.0.0` instead of a local script,
  passing a plan **file path**, with the exit code read from the step rather than from a
  pipeline.
- `scripts/cost-guard.sh` and `config/cost-guard-denylist.json` are **deleted** from this
  repository, along with any local guard test that only existed to test them.
- `config/cost-guard-action.txt` records the pin, and a contract check asserts every
  `uses:` of the action matches it.
- Any contract check in this repository is updated **in the same commit** and still fails an
  unguarded pipeline.
- The three exit outcomes still gate: denied fails the job, clean passes, and **undecidable
  fails** rather than passing.
- No workflow gains a `pull_request` trigger that did not already have one.
- Every workflow that runs on push to the default branch also accepts `workflow_dispatch`.
  An auto-merge push raises no events, so a workflow without it never runs on a merged
  commit.

## Check

From the repository root, with no cloud authentication:

```bash
! test -f scripts/cost-guard.sh
! test -f config/cost-guard-denylist.json
scripts/check-ci-contract.sh 2>/dev/null || echo "no contract check here — say so in evidence"
```

Then the part that cannot be argued from the diff — show the output in the pull request:

1. **A denied plan fails the job in CI.** A fixture plan containing a denied create is
   enough; it needs no cloud.
2. **An undecidable plan fails the job**, not passes. This is the fail-closed property and
   it is the one most easily lost behind a wrapper.
3. **A clean plan passes.**
4. **Show a contract check failing** when the guard step is deleted from the workflow. A
   contract check that accepts an unguarded pipeline is worse than none.
